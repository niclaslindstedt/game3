---
title: When main and the branch each added lines to a file near the §20.5 cap, the merged file is over it though neither side was — fold the BRANCH's hooks into its own module, and re-run the timing-margin tests
date: 2026-09-17
scope: engine/game/craft.ts, tests/tricks_test.ts
concepts: [rebase, file-size, parallel-work, timing-margins]
---

`craft.ts` was 989 lines on the branch and under the cap on main; the
rebase put it at 1007 with no conflict in it at all, because each side
added its own twenty lines to different stretches. `file_size_test` is the
only thing that says so, and CI's is the first run of it on the merged
tree. The fix that does not touch main's work: take the branch's two
call-sites (the bars and the body's drag under the water) and fold them
into one function in the branch's own module, called once — the file is
under the cap and the diff against main reads as the branch's alone.

And a staged ride that ends in a fixed number of seconds is a margin the
other side's physics can spend: the wash landed the marlin's clean
surfacing a few hundredths later, and the combo's one-second link window
then closed at 6.03 s in a six-second ride, failing an assertion about a
combo that was actually won. Read the events before touching the rule;
the answer was a seventh second.
